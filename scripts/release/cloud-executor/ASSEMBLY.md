# Optional compiled engine assembly (FIN17)

The normal `bash scripts/run-build.sh` full build is unchanged. This optional path reuses actual `out-vscode-min` and `out-build` compiler output, not npm downloads and not an old released application. It does not reuse Studio extension output, private Service source/packages, signatures, native acceptance, approvals or release receipts.

Prepare the exact fork/upstream tree and patches through the normal audited workflow first. Apply product overrides and install dependencies normally. Use a disposable native builder, Node22.22.1, its current npm/Rust/compiler tools, matching `OS_NAME`/`VSCODE_ARCH`, and the normal `hypeproof-studio.env`. No `get_repo`, reset or clean runs inside either optional phase.

```sh
HPS_ASSEMBLY_MODE=compile-base HPS_ASSEMBLY_CACHE="$RUNNER_TEMP/engine-base" bash scripts/run-build.sh
# Capture manifestSha256 from the command result in a trusted build receipt.
# Store only this new immutable directory through the authorized artifact path.
HPS_ASSEMBLY_MODE=assemble HPS_ASSEMBLY_CACHE="$RUNNER_TEMP/engine-base" HPS_ASSEMBLY_MANIFEST_SHA256="$PINNED_MANIFEST_SHA256" bash scripts/run-build.sh
```

`assembly.mjs compile-base CACHE` and `assembly.mjs assemble CACHE SHA256` are also executable entrypoints when the caller has already performed the standard environment checks. Neither silently falls back to a full build. Cache export refuses an existing destination; assemble requires an independently pinned manifest hash and verifies every file/hash/size and restores pinned safe modes, exact inventory, upstream/fork commit, actual prepared engine src/build/builtin source closure, fork patch/overlay/build inputs, toolchain versions and build flags. Linked inputs/destinations and overlapping cache/engine paths are refused. Current product semantic values, including version, are part of the key; changing them requires a new compile base. Studio extension source is deliberately excluded and always rebuilt. Changing unrelated Studio code may therefore reuse the same engine closure, while arbitrary version/branding/engine changes cannot.

The compile phase executes `vscode-min-prepack` **and** `core-ci`: modern esbuild upstream prepack alone does not compile the core. The assemble phase restores only the two verified core output directories, invokes existing Service bootstrap/Studio inject (including vendor validation), rebuilds all builtin extensions and media, generates policy files, then uses `vscode-PLATFORM-ARCH-min-ci` and the actual Rust CLI builder. The upstream `min-packing` task must not be called as reuse assembly: modern upstream recompiles esbuild core there. The current package-only task remains responsible for target-native extensions/dependency patches. Missing or changed upstream tasks fail the real commands.

The resulting package tree must contain the current candidate commit, the newly stamped extension version, and the freshly rebuilt extension bundle bytes. `vscodium-base/hps-assembly-receipt.json` records the original compile source separately from current candidate source and explicitly reports `UNSIGNED_PACKAGE_TREE`/`releaseEvidence:false`.

Downstream native workflows must perform their existing fresh product/Info.plist version restamp, normal signing/notarization, distributable archive/Inno packaging, build-contract/hash recording, isolated installed acceptance and manager review. For Windows, replace only compilation and package-tree production; keep the later current-version restamp and `prepare_assets.sh` that produce real installers. Do not run the existing `build/windows/package.sh` after assembly, because it calls `min-packing` and recompiles. For Mac, keep the existing post-build plist/product restamp and normal signing path. Optional native workflow wiring is included and remains disabled by default.

No native compiler, signer, package publication, old artifact mutation, cold/warm performance comparison, binary equivalence claim or installed acceptance was performed in this implementation. Tests use synthetic compiled files and exercise real filesystem verification/restoration, stale identity/inventory/symlink failures and fresh packaged-extension checks. Actual Mac/Windows source-equivalence, toolchain compatibility, signing and installed behavior remain NOT_RUN until independently executed on the exact source/cache/package identities. Existing released N−1 behavior is unchanged.

## Controlled native workflow wiring

Mac and Windows expose `engine_assembly_mode` with default `full`. `compile-base` produces a new base then assembles freshly in the same run. `assemble` consumes a numeric `engine_cache_artifact_id` plus `engine_cache_manifest_sha256`. Paths are fixed under `RUNNER_TEMP/hps-compiled-engine`; no URL/path/producer revision input exists. Both optional modes require `RELEASE_ENGINE_ENABLED=true`, separately configured `RELEASE_ENGINE_ASSEMBLY_ENABLED=true`, and an explicitly reviewed exact `RELEASE_ENGINE_ASSEMBLY_WORKFLOW_SHA`. Compile-base must run at that exact reviewed source SHA. Before candidate checkout, workflow-owned guards reject optional input refs/candidate SHAs that differ from the workflow commit; a trusted producer cannot execute arbitrary candidate-ref helper scripts. Ordinary full/tag builds follow their prior path.

Reuse admission makes bounded GET-only GitHub reads, checking fixed canonical repository ID, immutable numeric artifact ID, fixed platform name, provider archive digest, expiration/size, reviewed producer head SHA, exact native workflow path and a successful completed current run/attempt. The downloaded manifest must hash to the independent expected pin and identify that same reviewed compile source. Cache content and current compile inputs are verified before code/packaging execution. Actions transport can flatten file permissions: byte inventory is verified first, then only safe original modes from the pinned manifest are restored. Hidden files are included only inside the two compiler-output directories and the hash-only manifest, so inventory remains exact.

Cache export is a **new governed storage effect**, not an assumed free cache write. Trusted Service execution configuration must provide `build-mac:compiled-engine-store` and/or `build-win:compiled-engine-store`, kind `artifact-store`, exact artifact names `compiled-engine-darwin-arm64` / `compiled-engine-win32-x64`, approved workflow role, and sufficient independently proven storage capacity. The workflow authorizes before upload and reconciles its immutable numeric artifact ID after upload. Missing/unobservable storage proof or absent configuration blocks export. Neither enabling variables nor storage resources were created by this implementation.

The Mac workflow retains its existing fresh plist/product restamp, signing and package checks. Windows optional assembly bypasses the old compilation and `build/windows/package.sh` steps and then joins the same fresh product restamp/`prepare_assets.sh` installer path. The default full path retains those original compile/package commands. Source/build-contract enforcement must pin `assembly.mjs`, `assembly-phases.sh`, `assembly-workflow.mjs` and `scripts/run-build.sh` alongside reviewed native workflows before enabling governed reuse. The assembly receipt includes the current Service package-pin file hash and exact newly rebuilt extension hash, separate from reusable engine provenance.

Artifact transport permission handling follows the upstream [Actions artifact permission-loss contract](https://github.com/actions/upload-artifact#permission-loss); cache file bytes and externally pinned manifest remain mandatory.

Before compiled-cache authorization, `workflow-gate.mjs` measures the fixed `RUNNER_TEMP/hps-compiled-engine` tree, rejects links/nonregular files and relative paths over 4096 UTF-8 bytes, and requires an explicit `RELEASE_ENGINE_ASSEMBLY_MAX_ARTIFACT_BYTES` (positive integer, at most 2 GiB). The conservative ZIP/ZIP64 bound is `ceil(totalFileBytes*1.02) + fileCount*147456 + 1048576`: raw-deflate level-zero growth, maximum local/central per-file extra/header fields, path bytes, and global end-record allowance. Large/file-heavy inputs that cannot fit this bound are refused rather than uploaded. Upload uses compression level zero, no overwrite, fixed seven-day retention and the same size/retention envelope for authorization and immutable-artifact completion.

The compiled storage effect is `{kind:'artifact-store',artifactName,maxBytes,retentionDays:7}`. Its trusted Service path must have matching `maxArtifactBytes`, `retentionDays:7`, `unit:'byte-days'` and capacity at least `maxArtifactBytes*7`; completion must reject observed artifact size above that bound. Existing legacy artifact paths keep their previous effect shape. Missing matching Service capacity/source contract blocks this optional path.

Fresh package validation compares the complete injected `dist` (including vendor), `webview-ui/dist` and `media` file/hash/size/mode inventories with the newly rebuilt source extension, in addition to the current product commit and extension version. The receipt includes `shippedClosureSha256`; a matching host entry alone cannot attest a stale webview/vendor/media tree.
