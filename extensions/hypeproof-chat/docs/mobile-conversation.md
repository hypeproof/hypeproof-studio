# Existing desktop conversation → iPhone

The command **HypeProof: iPhone과 이 대화 연결** (also visible in the **iPhone 연결** status bar) asks explicit consent before uploading the selected personal conversation's user/assistant text. Account tokens stay in the existing SecretStorage account session. Classroom/instructor/temporary conversations are excluded. The Service stores a server copy; transport uses TLS, not end-to-end encrypted storage.

The original TaskWorkspaceStore remains authoritative. A local binding stores only account session, activity, hashed workspace, task, title, upload digests and one accepted request marker. There is no second desktop transcript or execution queue. Polling is serialized between windows with a separate existing accountLock instance. Message upserts have deterministic event IDs; tools, files, raw audio and message metadata are excluded. The current selected task must match; execution waits for unsent input, queued input, restore, verification and active streams to settle.

Phone requests use their UUID as the existing desktop userMessageId. The Service must atomically grant the first claim; the desktop then saves the accepted marker before invoking the ordinary typed send boundary. The existing provider, saved history, cost/account checks and coach policy remain in use. Remote turns activate the existing planning tool gate, skip executable shortcuts and attached-file consumption, and do not create a separate coach prompt or approved plan. Completed is sent only after the original history saved an answer and text upserts succeeded. A request found running after interruption becomes unknown and is never automatically replayed.

Account invalidation, scope changes and disconnect fence asynchronous work; active remote work is stopped on invalidation. A generic rollout/host-permission 403 preserves account credentials. Disconnect stops sharing while retaining the server copy. **서버 대화 사본 삭제** deletes the server copy and binding while preserving original desktop history. One conversation binding is supported per desktop global storage. Different task selection waits; it does not switch tasks remotely.

## Focused validation

Run `npm run test:mobile-conversation`, `npm run typecheck` and `npm run build:extension` in this extension. Existing `test/plan-first.test.mjs`, `test/plan-first-browser-loop.test.mjs` and `test/account-session.smoke.mjs` exercise reused runtime/auth gates. Controller tests cover duplicate processing, crash recovery, saved-marker failure, failed upload, scope/account fences, drafts, server deletion, safe text projection and existing credential transport. Provider harness tests exercise the original disk store and typed-message entry with VS Code/provider fixtures.

These are local source/bundle and fixture tests. They do not establish installed desktop acceptance, real provider completion, live Service deployment, iPhone pairing, microphone behavior, or physical multi-device roundtrip. Those require the shared Service API and account plus installed desktop/iPhone acceptance: connect with disclosure, read original text, explicitly submit one phone request, observe one corresponding desktop user UUID and saved answer, then confirm phone sees that answer, disconnect and delete the server copy without losing desktop history.
