## 1. 무엇이 업로드되나

업로드 단위는 **세션 디렉토리 하나**이고, 파일은 정확히 3종이다. 서버 allowlist
가 그 외 파일명을 거부한다(`worker/src/routes/logs.ts` `ALLOWED_FILES`).

| 파일 | 내용 |
|---|---|
| `session.meta.json` | 세션 id(UUID) · 코호트 · 사용자 핸들 · 시작 시각 · 개발호스트 표식 |
| `events.jsonl` | **질문 원문** · **AI 응답 원문** · **HTML 결과물 스냅샷** · 결과물 저장 승인 여부 · 요청 단위 토큰 usage 4종 · 행동 이벤트 · 턴 종료(비용 포함) |
| `manifest.json` | 위 파일 목록 + sha256 (완결 표식) |

`events.jsonl` 이 개인정보 관점의 핵심이다. 레코드 종류별로 (`extensions/hypeproof-chat/src/sessionSpool.ts`):

| 레코드 | 담긴 것 | 상한 |
|---|---|---|
| `prompt` | 참가자가 코치에게 **친 문장 그대로** | 20,000자 |
| `response` | 참가자 화면에 **보인 AI 응답 원문**과 상태(`ok`·`aborted`·`error` — 중단·오류 전까지 보인 부분 포함) | 200,000자 |
| `artifact_snapshot` | 미리보기에 띄우거나 저장된 **HTML 결과물 본문**, 업로드 직전 작업 폴더의 실제 `index.html`(`session_end`). 경로는 파일명만, 같은 내용은 세션당 1회 | 200,000자 |
| `artifact_approval` | 결과물 저장을 승인했는지 여부 + 내용 sha256 (본문 없음) | — |
| `usage` · `turn_end` · `workflow` · `lesson_binding` | 토큰·비용 · 턴 결과 · 행동 이벤트 · 수업 묶음 표식 (원문 없음) | — |

상한에 걸리면 자르되 무성 절단은 없다 — `text_truncated`/`content_truncated: true`
와 원래 글자 수를 같이 남긴다.

들어 있지 **않은** 것: `index.html` 외의 작업 폴더 파일, 전체 파일 경로, 화면 캡처,
이메일·전화번호 등 별도 수집 항목. 신원은 강사가 발급한 **핸들**(예: `pilot-01`)
이며 실명이 아니다. 단 질문·응답·결과물 본문에 참가자가 직접 적은 내용(병원 이름,
환자 사례 등)은 그대로 들어간다 — 고지문(§6)이 이 점을 말해야 하는 이유다.

## 2. 왜 모으나

두 가지뿐이다(#580).

1. **비용 통제** — 어떤 질문이 비싼지를 질문 원문 옆에 붙여서 본다. 요청 1건 =
   레코드 1건이라 "턴당 $0.024" 같은 값이 바로 나온다.
2. **커리큘럼 개선** — 어디서 막히는지, 어떤 표현이 통하는지를 감이 아니라
   데이터로 본다.

3. **연구 (선택, 별도 동의)** — 역량 전이 연구(studio#1051). 수업 뒤 실제 사용
   기록에서 무엇이 이어지는지를 본다. 이 목적에는 아래가 **전부** 필요하다:
   - 해당 회차 참가자 각자의 **별도 서면 연구 동의**. 동의는 제품 밖(서면)에서
     받고 보관한다. **제품은 이 동의를 기록하거나 확인하지 않는다** —
     `analytics.upload_session_logs=true` 는 연구 동의가 아니다(클래스룸 수집
     경로의 규율과 같다: `docs/requirements/classroom-admin.md`).
   - 데이터 책임자(Jay)와 해당 수업 책임자의 승인. 이것도 제품 밖에서 받는다.
   - **성인 코호트만.** 미성년 코호트의 기록은 동의 여부와 무관하게 연구 목적에
     쓰지 않는다(§4).

   연구 동의가 없는 참가자의 기록은 1·2 목적에만 쓰고 연구 분석에서 제외한다.
   업로드 경로·파일·보존 기간은 세 목적이 같다 — 연구용 별도 수집 경로나 별도
   플래그는 없다.

마케팅·광고·외부 제공·모델 학습에는 쓰지 않는다.

## 3. 언제 올라가나 — 네 조건이 **전부** 참일 때만

하나라도 거짓이면 업로드는 일어나지 않는다(fail-closed).

| # | 조건 | 현재 상태 |
|---|---|---|
| 1 | 워커가 업로드 라우트를 갖고 배포돼 있다 | ✅ 2026-08-19 배포 (afab426) |
| 2 | 그 코호트 프로필에 `analytics.upload_session_logs: true` | 2026-10-05(bed32b89) 기준 ON: `canary-sdk-contract`, `kids-workshop-s1`, `kids-2026-grade-5-6-s1`(§4 동의 표식). 성인 실코호트 전부 OFF |
| 3 | 사용자가 **버튼을 누른다** | 자동 업로드 경로 없음 (REQ-Q9) |
| 4 | 세션 신원 = 토큰 신원 | 공용 PC 에서 남의 세션이 내 이름으로 올라가지 않는다 |

②가 거짓이면 서버가 `403 upload_disabled` 로 거부하고 클라이언트 UI 에 버튼조차
뜨지 않는다. **2026-08-19 프로덕션 실측으로 양쪽 방향 확인**: canary 는 R2 적재
성공(바이트 대조), 치과 파일럿(성인, OFF)는 403 거부.

## 4. 미성년

아동 코호트(`audience.parent_coaching=true` 또는 `age_range` 상한 ≤ 12)가 이 플래그를
켜면 `validate.py` 가 기본 HARD FAIL 로 막고, CI 가 그 검증기의 자기 테스트까지
돌린다. 예외는 하나 — 프로필에 `analytics.child_upload_consent`(누가·언제 보호자
동의를 확보했는지 적은 문자열)가 있으면 WARN 으로 내려간다(rules.yaml
`child.upload_consent_key`). 이것은 **검증이 아니라 주장의 기록**이다. 2026-08-21
기업 고객 두 코호트가 이 경로로 켜졌다(보호자 사전설문).

**연구 목적(§2-3)에는 미성년 기록을 쓰지 않는다.** 보호자 동의가 있어도 마찬가지다.
그 동의는 비용 통제·커리큘럼 개선·갤러리 학습 리포트를 위한 것이고, 연구 동의가
아니다. 미성년을 연구 대상으로 삼으려면 별도 절차(법정대리인 연구 동의 서식,
연구 계획 재검토, 이 문서의 재검토)가 먼저다. 순서를 뒤집지 않는다.

## 5. 보존 기간

| 위치 | 기간 | 근거 |
|---|---|---|
| 참가자 PC (로컬 스풀) | 업로드 성공 후 **3일** 뒤 삭제. 미업로드분은 총량 200MB 캡까지 보존 | REQ-Q6 · REQ-Q12 |
| R2 (`studio-logs/`) | **90일** 후 자동 만료 | 아래 |
| lab Supabase `session-logs` 버킷 (미러) | **만료 설정 미확인** | `worker/src/routes/logs.ts` 10단계 — `GALLERY_LOGS_BASE` 가 설정된 배포에서 같은 바이트를 lab 으로 릴레이한다(2026-08-21, #661). 만료 정책은 #678 에서 열려 있다 |

연구 목적(§2-3)을 더해도 보존 기간은 바뀌지 않는다. 분석에 더 긴 기간이 필요하면
원문을 오래 두는 대신 연구 저장소 쪽 접근통제 사본·집계본으로 옮기는 결정을 따로
한다(이 문서 범위 밖).

**미러가 해소되기 전까지 "90일 후 자동 삭제"는 R2 사본에 대해서만 참이다.** 새
회차에 §6 고지문을 쓰기 전에 #678 의 상태를 확인한다.

**90일을 고른 이유**: 한 코호트 시리즈(최대 4회차, 주 1회 = 약 1개월)가 끝나고
분석까지 마치는 데 필요한 창을 덮으면서, 목적 달성 후 지체 없이 파기한다는 원칙을
지키는 가장 짧은 값. 분석이 더 걸린다면 기간을 늘릴 게 아니라 **집계본을 남기고
원문을 버리는 쪽**이 맞다.

적용 상태 (2026-08-19 설정·확인):

```
bucket: hps-traces
rule:   studio-logs-retention-90d
prefix: studio-logs/
action: Expire objects after 90 days
```

프리픽스를 `studio-logs/` 로 좁힌 것은 같은 버킷의 다른 두 용도(`turns/` 턴 원문,
`backup/d1-` D1 백업 — 자체 회전 보유)를 건드리지 않기 위해서다.

## 6. 참가자 고지문

수업 시작 시 구두로 읽거나 안내문에 그대로 붙일 수 있는 문안. **업로드 버튼을
누르기 전에** 전달되어야 한다.

> **오늘 활동 기록에 대해 알려드립니다.**
>
> 수업 중 여러분이 코치에게 입력한 질문, 코치(AI)의 답변, 여러분이 만든 웹페이지
> 결과물, 그리고 그에 든 비용·토큰 정보가 여러분 PC 에 기록됩니다. 질문과 결과물에
> 직접 적은 내용(병원 이름 등)도 그대로 기록되니, 환자 정보처럼 남기면 안 되는
> 내용은 입력하지 말아 주세요. 이 기록은 **여러분이 "오늘 활동 기록 보내기" 버튼을 직접
> 누르지 않는 한 PC 밖으로 나가지 않습니다.**
>
> 보내주시면 저희는 이것을 **수업 비용을 파악하고 커리큘럼을 개선하는 데에만**
> 씁니다. 광고나 외부 제공, AI 모델 학습에는 사용하지 않습니다.
>
> 보관 기간은 **90일**이고, 이후 자동 삭제됩니다. PC 에 남은 사본은 전송 후
> 3일 뒤 정리됩니다.
>
> 보내지 않으셔도 수업에는 아무 영향이 없습니다. 보내신 뒤 삭제를 원하시면
> 강사에게 말씀해 주세요.

마지막 문장은 약속이다 — **지킬 수 있을 때만 넣는다.** 현재 개별 삭제는 R2 키
프리픽스(`studio-logs/<코호트>/<핸들>/`)로 수동 삭제가 가능하다. Supabase 미러
사본도 같이 지워야 약속이 지켜진다(§5).

**2026-10-05 이전 판 고지문**은 "질문과 비용·토큰 정보"만 말했고 응답·결과물을
말하지 않았다. 이미 그 문안으로 고지받은 회차(2026-08-22 기업 고객)는 **재고지하지
않기로 결정했다**(조민한, 2026-10-05 — #1512 댓글).

연구 동의(§2-3)를 받는 회차는 위 문안 끝에 한 문단을 더한다. 동의서 자체는 별도
서면이다.

> 이번 수업은 HypeProof 연구에도 참여합니다. 별도로 드린 연구 참여 동의서에
> 동의하신 분의 기록만, 수업이 끝난 뒤의 기록을 포함해 연구 분석에 쓰입니다.
> 동의하지 않으셔도 수업과 이후 사용에는 아무 영향이 없습니다.

## 7. 첫 opt-in 대상

성인 코호트부터. 구체적으로 **치과 원장 트랙**
(`dental-copyclone-2026-s1`) 이 후보다 — 성인이고, 이미 이 파이프
라인의 데이터가 가장 많이 쌓일 트랙이며, 미성년 절차 문제가 없다.

켜는 절차:

1. §6 고지문을 해당 회차 참가자에게 **실제로 전달**한다(연구 회차는 연구 동의
   문단과 별도 서면 동의서까지)
2. 프로필에 `analytics: { upload_session_logs: true }` 한 줄 추가 (PR)
3. `npm run validate-profiles` 초록 확인 (아동 코호트였다면 여기서 HARD FAIL)
4. 워커 배포

**1번이 2번보다 먼저다.** 동의 없이 켠 수집은 켜지 않은 것만 못하다.
