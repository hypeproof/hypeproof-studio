## Observed, not changed (follow-ups)

- A skill's request on the coach route is shaped by the cohort's lesson: on the Anthropic path `translate()` sends the profile's system prompt and its tools (for the canary profile `web_search` and the browser tools, with the Experiment Browser and AI Verify tools while the switch is on) with the Experiment skill's prompt. The ten live answers were still one JSON object each and met the gate. Whether a skill request should carry the lesson's system prompt and tools is `cr-gateway`'s capability routing (CR-30), not this item's.
- The live provider time includes the coach route's own handling in process (token, session, admission, translation) and the network from this Mac to `api.anthropic.com`. Production adds the App-to-Service network and the proxy hop; the run's margin to the target (15 s at the slowest) is what that has to fit in.
- Local workerd D1 suites and this Mac's loopback ports (not caused by this slice; not changed). macOS gives outgoing connections 16,384 ephemeral ports (49152 to 65535) and holds a closed one in TIME_WAIT for about 30 s (`net.inet.tcp.msl` 15000). One run of the cr-review suite on local workerd D1 peaks at 12,000 to 15,000 sockets in TIME_WAIT (sampled every 2 s: 12,016 to 14,940 over the thirteen runs of the second campaign, 14,225 in the gate run). Run one at a time, each after the count fell, every run here passed, and none of the campaign's runs failed for the environment. Two at once do not fit: in review, D1 runs made while another review lane's D1 suite ran on the same Mac failed with `TypeError: fetch failed`, `origin/main`'s version of the file included. The recorded-provider case adds a little to the peak: alternating runs, each started below 300, peaked at 13,894 and 13,304 for `origin/main`'s file and at 14,148 and 14,248 for this head's. So local D1 suites have to run one at a time machine-wide, which the app lock does not cover, and a lighter harness (one Miniflare dispatcher reused across requests) would leave room. CI runs these suites on `ubuntu-latest`, whose port range and TIME_WAIT handling differ and which nothing here measured: watch `test:cr-review:d1` on this PR, and if it flakes, reuse the dispatcher or move the recorded-provider case to its own D1 script.
