   실제 App에 주입된 확장 버전도 확인한다. 운영 학생 자격과 개인 대화는 fixture로 사용하지 않는다.
4. 먼저 정상 동작과 심은 결함으로 검사기를 점검한다. UI 캡처·실제 도구 이벤트·파일 읽기·
   요청 payload 중 해당 주장에 필요한 증거를 확보한다. AI의 성공 문장을 도구 실행 근거로 쓰지 않는다.
5. 시나리오별 PASS/FAIL/BLOCKED/NOT RUN, 실행 명령·commit·환경·관측·증거 경로를 남긴다.
   미구현은 NOT RUN, 필요한 실기 환경 부재는 BLOCKED 사유로 기록하며 통과 분모에서 숨기지 않는다.

합성 홈페이지 A(정상), B(미리 심은 결함 4종)를 시작 파일 해시로 고정한다.
