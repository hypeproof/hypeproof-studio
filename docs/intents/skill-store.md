# 공개 유료 스킬 스토어 — Product Intent

상태: **sponsor 정의(2026-11-02~03 TJ 질의응답) · 2026-11-03 개정(스킬 보관 설계 v1, 데모 영상 v9 기준) · 구현 중.** 실제 지급·실 결제 키·통신판매중개업 신고·세무 의견은 사람 관문 [#3419](https://github.com/hypeproof/hypeproof-studio/issues/3419) 뒤에 있다(실 결제 최소 2026-12-21). 운영 활성화는 레드팀 출시 차단 항목 F1(첫 서버 조립 때 환불권 종료, 구현됨)과 F10(배포 권한과 분리된 외부 KMS, #3419의 사람 관문)이 닫힌 뒤에 한다.
Sponsor: TJ. [Epic #3418](https://github.com/hypeproof/hypeproof-studio/issues/3418).

## Product Intent

**Studio 사용자가 코치와 함께 만든 스킬에 값을 매겨 공개 스토어에 올리고, 다른 사용자가 Studio 안에서 카드로 사서 자기 계정으로 실행하며, 판매자는 정산 장부에서 판매와 자기 몫을 확인한다. 그 판매를 처음 이끈 강의의 강사와 교육 파트너는 HypeProof 수수료에서 영구히 몫을 받는다.**

상업·자격 규칙의 값은 이 문서에 쓰지 않는다. 값은 버전이 붙은 [스킬 스토어 정책](../policy/skill-store-policy.md)과 Service 설정에만 있고, 요구사항 행은 정책 키만 인용한다. sponsor는 정책 값이 바뀔 것으로 본다.

## 먼저 해결할 문제

강의에서 만든 스킬은 지금 그 수업 코호트 안에서만 쓰인다(#1603). 만든 사람이 그 스킬로 돈을 벌 길이 없고, 강의를 연 강사·교육 파트너가 수업 이후의 가치에서 받는 몫도 없다. 반대로 공개 판매를 열면 세 가지 위험이 생긴다.

- 스킬이 Service 밖의 능력(임의 MCP, 자격 증명, 주소록)을 끌고 들어와 구매자의 권한을 넓힌다(CGP-AGENT-38).
- 구매·환불·분배가 사람 판단으로 처리되면 정책이 바뀔 때 과거 판매를 다시 계산하게 된다.
- 미성년자 결제, 자전거래(같은 기기·카드·네트워크), 고가 상품 카드 심사 같은 결제 사고.

## 세 가지 Intent

| ID | 의도 | 성공을 관찰하는 방법 |
|---|---|---|
| INT-ST-01 | 판매자가 수동 승인 없이 스킬을 올린다. 자동 검사가 CGP-AGENT-38 경계를 그대로 지킨다: Service가 허용한 도구만, 자격 증명·토큰·주소록·개인정보 없음, 외부 MCP 설정 없음. 검사에 걸리면 목록에 오르지 않는다. 등급 한도(`tier.*.cap_krw`)와 사람 검토 기준(`listing.auto_publish_max_krw`)은 정책이 정한다. | 설치된 App에서 B가 한도 안의 가격으로 올린 스킬이 검사 직후 공개 목록에 보인다. 키·전화번호·`mcpServers`가 든 스킬은 이유와 함께 거절되고 Service에 저장되지 않는다. |
| INT-ST-02 | 성인 구매자가 Studio 안에서 카드로 사고, 설치하고, 자기 이용량으로 실행한다. 첫 실행 전 `refund.window_days` 안의 환불은 전액이고, 첫 실행 뒤에는 환불이 없다는 사실을 구매 전에 보여 준다. 14~18세는 무료 설치만 하고, 강사 코드 전용 14세 미만 코호트는 스토어에 들어오지 않는다. | A가 결제창(PG 테스트 키)에서 결제하면 App에 설치가 보이고, 실행하면 Service가 판매자 단계와 A의 조정을 서버에서 조립해 그 턴에 넣고 A의 이용권에서 차감된다. A의 기기와 통신에는 판매자의 비공개 지침이 남지 않는다. 실행 전 환불은 결제 취소와 설치 삭제로 끝나고, 첫 서버 조립 뒤에는 환불 버튼이 사라진다. A는 단계를 끄거나 말투·추가 요청·단계 교체로 자기에게 맞게 고치고, 그 조정은 A의 것으로 남는다. |
| INT-ST-03 | 모든 판매·환불·정산 줄이 계산에 쓴 `policy_version`을 남긴다. 결제 수수료를 먼저 빼고 `split.seller_bps`/`split.commission_bps`로 나누며, 소개 수수료(`referral.*`)는 HypeProof 몫에서 판매자가 처음 들어온 강의의 파트너·강사에게 간다(영구 귀속). | B의 정산 화면이 판매 한 건마다 판매가, 결제 수수료, B의 몫, HypeProof 수수료와 그중 파트너·강사 몫, 정책 버전, 환불 가능·지급 보류 상태를 보여 준다. 환불은 같은 정책 버전의 음수 줄로 되돌린다. 미성년 판매자는 장부를 보고, 지급은 "연결된 성인 필요"로 표시된다. |

## 첫 사용자와 첫 장면

1. B(성인, 본인인증 완료, 2026-10 강의로 가입)가 Studio의 스킬 스토어 → 판매 탭에서 코치와 만든 회의록 정리 스킬을 10,000원에 올린다. 자동 검사 뒤 곧바로 목록에 오른다.
2. A(성인)가 시작 화면의 「스킬 스토어」를 열어 환불 규칙을 읽고 카드 결제를 누른다. 브라우저의 결제창에서 결제를 마치면 App의 「내 스킬」에 설치가 보인다.
3. A가 설치한 스킬을 퀘스트로 실행하면 Service가 판매자 단계를 서버에서 조립하고, 그 턴의 모델 사용량은 A의 이용권에서 나간다. 이 순간부터 환불 버튼이 사라진다. App의 실행 진입점과 단계 편집 화면은 #1605(퀘스트 스킬)가 main에 들어온 뒤의 슬라이스에서 나온다.
4. B가 판매 탭의 정산 내역에서 그 판매의 결제 수수료, 80/20 분배, 파트너·강사 몫, `v1`을 본다. 실제 지급은 아직 없다는 문장이 함께 보인다.

## 첫 버전의 범위

- 포함: 스킬만(단계별 공개 층·비공개 층), 공개 목록과 검색, 계정 필요 구매·설치, PG **테스트 키** 결제, 실행 전 환불, 판매자 등급 한도, 같은 기기·카드·IP 차단, 서로 다른 구매자 신고 3건 자동 내림, 정산 장부, 서버 보관과 서버 조립, 버전별 봉투 암호화, 구매자 조정(overlay), 판매자 업데이트와 확장 시 재동의.
- 제외: 학습자 작품·공식 과정 판매, 실제 지급 이체, 보호자 연결 지급, 수동 사전 심사.
- 판매자에게 하는 약속: 원본은 구매자 기기로 배포되지 않고, 유출은 추적되며, 약관이 추출을 금지한다. "복사할 수 없다"고 약속하지 않는다. 모델은 실행 때 평문을 읽어야 하므로 구매자 기기에서 복호화하는 방식으로는 구매자에게 숨길 수 없다.
- 대신 처리: 휴대폰 본인인증·KYC·통신판매 신고 상태는 제공자 계약 전까지 운영자 경로(`/admin/store/profiles/:account`)로만 바뀐다. 나이는 태어난 해 1회 자기 신고이며 경계 연도는 미성년으로 본다.

## 기존 의도와의 충돌 (기록, 해소하지 않음)

- #1603(코호트 스킬 스토어)은 공개 마켓과 과금을 범위 밖으로 두었다. 이 Epic은 그 위의 새 범위다. #1603의 게시·목록·설치 경로는 아직 main에 병합되지 않아(Service PR #50·Studio PR #1605 Draft) 이번 슬라이스는 별도 경로로 구현했다. 병합 시 하나로 합치는 일은 후속이다.
- CGP-AGENT-38은 학습자 공개 설치를 거부하고 큐레이션 카탈로그를 둔다. 즉시 게시는 위 자동 검사가 같은 경계를 강제할 때만 받아들인다. 검사는 과잉 거절 쪽으로 설계했다.
- Curriculum Runtime PRD §9의 "범용 AI 모델 마켓" 비목표: 이 스토어는 그 런타임의 P0 밖이다.
- #1782의 Toss 단일 가맹점 계정으로 스토어 상품을 팔지 않는다. 스토어는 별도 키(`HPS_STORE_TOSS_*`)를 쓰고, 코드가 `test_` 키만 받는다.
