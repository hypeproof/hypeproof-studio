Studio 사용자

매뉴얼 홈Studio 사용자Owner·멤버운영자개발자
상태: 후보 구현 · 통합 대기. 이 문서는 로컬 후보 코드와 지정된 작업 계획을 읽어 작성했습니다. 배포되었거나 사람이 받아들였다는 뜻이 아닙니다. 실제 화면 캡처는 아직 없어 아래 칸을 모두 NOT_RUN으로 표시합니다. 화면 이름이 다르거나 기능이 안 보이면 이 문서대로인 척 진행하지 말고 현재 버전에서 기능을 사용할 수 있는지 확인하세요.

목적

내가 선택한 작업 폴더 안에서 파일을 찾고 저장합니다. Studio가 다른 폴더를 대신 고르거나 결과를 자동 게시하지 않습니다.

준비

  • 수업이나 개인 작업에 사용할 폴더를 알고 있는지 확인합니다.
  • 기존 파일을 고치기 전에는 파일을 열어 내용과 현재 폴더를 확인합니다.
  • 로그인·활동 연결이 필요한 수업 폴더라면 강사가 안내한 계정 흐름만 사용합니다. 암호나 토큰을 문서·채팅에 붙이지 않습니다.

파일과 폴더 열기

  1. Studio에서 File → Open Folder를 선택하고 작업 폴더를 엽니다. 폴더가 열리면 왼쪽 Explorer에서 폴더와 파일 목록을 확인합니다.
  2. 새 폴더나 파일이 필요하면 Explorer에서 해당 폴더를 선택하고 새 폴더/새 파일 아이콘을 사용합니다. 파일 이름과 위치를 확인한 뒤 편집 내용을 저장합니다.
  3. 기존 파일은 Explorer에서 파일을 열어 바꾸고 저장합니다. 저장 뒤 Explorer에서 파일 이름을 다시 확인하고 편집기에 변경 내용이 남아 있는지 확인합니다.

정상 결과: 선택한 폴더 이름이 작업 공간에 보이고, 만든 파일이 Explorer의 그 위치에 나타납니다. 예상한 내용이 들어 있는지 직접 다시 엽니다.

실패 시: 잘못된 폴더를 열었으면 File → Open Folder로 원래 폴더를 다시 고릅니다. 권한 오류가 나면 접근 권한을 가진 폴더를 선택하거나 강사/관리자에게 폴더 접근을 요청합니다. 저장이 안 되면 다른 이름으로 본인 폴더에 저장하고 원본은 덮어쓰지 않습니다.

폴더 바꾸기와 기존 작업 다시 열기

  1. 같은 수업에서 폴더를 바꾸려면 File → Open Folder를 사용해 목적지를 직접 고릅니다.
  2. Studio를 다시 열면 File → Open Recent에서 작업 폴더를 고르거나 File → Open Folder로 위치를 찾습니다.
  3. 수업 연결이 유효하면 현재 폴더의 수업 연결이 이어지는지 화면에서 확인합니다. 다른 수업·다른 서비스의 폴더에 연결됐다고 가정하지 마세요.

정상 결과: Explorer에 목적지 폴더가 보이고 현재 작업과 연결이 맞습니다. 다른 폴더 이름이나 다른 수업 정보가 보이면 채팅을 보내기 전 멈춥니다.

실패 시: 연결이 끊겼거나 접근이 거부되면 기존 결과물을 복사해 보존하고 강사에게 수업 이름, 오류 문구, 안전한 작업 ID만 전달합니다. 무한 재시도하거나 다른 사람 계정으로 로그인하지 않습니다.

공개 GitHub 지침 스킬 가져오기·선택·해제

이 후보의 명령 팔레트 항목은 HypeProof: GitHub 지침 스킬입니다. 외부 지침은 커리큘럼 지침과 별개이고 권한을 부여하지 않습니다. 공개 GitHub Markdown 지침과 정적 텍스트만 지원합니다.

  1. 명령 팔레트에서 HypeProof: GitHub 지침 스킬을 열고 GitHub에서 가져오기를 고릅니다.
  2. 공개 저장소 주소와 고정할 ref를 입력합니다. 권장 입력은 전체 40자리 commit SHA입니다. 폴더 주소라면 저장소 안의 상대 폴더도 지정합니다.
  3. 미리보기에서 저장소, 폴더, 고정 revision, 파일 목록과 지침 내용을 읽습니다. 예상하지 않은 지침이나 능력 요구가 있으면 취소합니다.
  4. 목록에서 스킬을 선택하면 그 작업 폴더에서만 적용됩니다. 다른 작업 폴더로 전역 적용되지 않습니다.
  5. 쓰지 않으려면 목록에서 스킬을 열고 사용 해제를 선택합니다. 저장된 항목 자체를 지우려면 목록에서 제거를 선택합니다.
  6. 바꿀 때 업데이트 확인으로 새 revision과 diff를 읽고 수용할지 고릅니다. 문제가 있으면 이전 revision 복구에서 되돌릴 버전을 골라 미리 확인합니다.

정상 결과: 목록에 출처와 고정 revision이 보이고 선택 상태가 표시됩니다. 오프라인일 때 저장된 스냅샷은 다시 읽을 수 있지만 새로 가져오기·업데이트는 네트워크가 필요합니다.

실패 시: 가져오기·검사 실패는 기존 선택과 작업 결과를 보존합니다. 연결을 확인하고 공개 저장소의 정확한 commit SHA를 다시 입력합니다. private 저장소, 이동하는 branch만 지정한 입력, 실행 파일·권한이 필요한 지침은 지원된다고 가정하지 마세요.

참고 이미지와 현재 화면 전달

현재 화면을 코치에게 보낼 때 실제 보고 있는 탭을 확인한 뒤 화면에 표시된 HypeProof: 현재 페이지를 코치에게 보내기 동작을 사용합니다. 주소만으로 이미지가 전달됐다고 가정하지 말고, 전송 성공/실패 안내를 확인합니다.

붙여넣기·첨부한 이미지가 채팅에 표시되면 실제 이미지와 파일 이름이 맞는지 확인합니다. 이전 대화의 이미지는 사용자가 “아까 올린 이미지 다시 봐줘”처럼 명시적으로 요청할 때만 다시 읽습니다. 해당 요청도 거부되거나 파일을 찾지 못하면 코치는 이미지를 본 척하지 않아야 합니다.

정상 결과: 올바른 탭/이미지가 전달됐다는 표시와 출처를 확인할 수 있습니다. 공유하면 안 되는 화면에는 개인정보·계정 정보가 없는지 먼저 살펴봅니다.

참고 이미지의 소유자·출처·사용 허가를 확인하고 요청에 기록합니다. 이용 권한이 불분명한 타인의 이미지나 개인정보 화면은 업로드하지 않습니다. 현재 페이지의 주소와 캡처는 같은 페이지에서 가져왔는지 확인하고, 실제로 전달된 이미지의 출처를 함께 봅니다.

실패 시: 다른 탭이 전송됐거나 캡처가 실패하면 현재 화면을 캡처했다고 말하지 말고 올바른 탭을 열어 다시 시도하거나 필요한 파일을 직접 첨부합니다. 민감 정보가 보이면 보내지 말고 안전한 사본을 준비합니다.

이미지 편집과 원본 복원

지원 범위: 이미지 편집은 현재 활동이 명시적으로 허용하고 Service 제공자가 설정된 경우에만 제안될 수 있습니다. 기능이 보이지 않으면 지금 버전에서 사용할 수 없는 것입니다. 채팅에 요청을 적는 것만으로 편집 기능이 생기지는 않습니다.
  1. 편집이 명시적으로 제공되면 작업 폴더 안의 RGB/RGBA PNG를 고릅니다. 이 후보는 PNG를 우선 지원하며 원본은 4 MB 이하여야 합니다. 투명 배경이 필요하면 그 점을 명확히 요청합니다.
  2. 바꾸려는 점과 보존할 부분을 구체적으로 적습니다. 투명 배경 편집은 PNG 결과가 나와야 합니다.
  3. 편집이 끝나면 원본과 새 결과를 나란히 비교합니다. 가장자리, 형태, 투명 영역, 세부를 확인합니다.
  4. 편집 결과를 채택하면 새 파일을 씁니다. 원본은 덮어쓰지 않습니다. 원본을 되돌리는 동작은 파일 덮어쓰기가 아니라 선택 경로를 원래 파일로 바꿉니다.

정상 결과: 새 결과가 images/edited/ 아래 별도 PNG로 저장되고 비교 화면에서 원본과 결과를 선택할 수 있습니다. 저장 성공만으로 품질 확인이 끝난 것은 아닙니다.

실패 시: PNG가 아니거나 크기·투명도가 맞지 않으면 지원되는 PNG 사본을 준비하거나 편집을 중단합니다. 제공자가 꺼져 있거나 연결이 실패하면 다시 시도하기 전에 사용량이나 진행 상태를 확인하고 중복 요청을 피합니다. 원본 파일을 직접 바꾸지 마세요.

멈춤·실패 복구

  • 답변을 기다리는 중에는 중지 동작을 한 번만 사용하고 입력 초안을 보존합니다. 중복 요청을 보내지 않습니다.
  • 화면이 멈추거나 결과를 확인할 수 없으면 대화 탭을 닫기 전에 파일 저장 여부를 살핍니다. 재시작 후 작업 폴더와 파일을 다시 엽니다.
  • 잘못된 결과는 원본 파일·이전 결과를 보존하고 새 사본에 다시 작업합니다.
