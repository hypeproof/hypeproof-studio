# DEV encrypted selection metadata handoff

The computer explicitly announces its selected request through the existing authenticated encrypted relay. `publishSelected(requestId, signal?)` returns a bounded publication receipt and exposes the same safe receipt in `view().publication`. The native control says `선택한 작업을 휴대폰에 알리기`. Service acceptance does not claim phone receipt or file approval. No production entry, route, account, key system, persistent store, budget or Service limit is added.

`hps-companion-selection/1` contains only revision1–64, paired invitation/claim identity, the strict existing `preview.read` request and `execution_authorized:false`. Request IDs are capped at96 characters for the existing device adapter. No paths, HTML, names, tokens or keys are included. Transport ID is `selection_` plus SHA256(exact UTF8 JSON). Metadata stays≤2032 bytes.

The browser-safe receiver accepts messages already authenticated/decrypted by the current device cipher. Paired account/device/host/workspace/project and invitation/claim digests must match; the first host declaration introduces selected task/version/epoch/artifact metadata, never authority. Optional known task context narrows it. Higher revisions replace current metadata only after validation; exact duplicates are idempotent, valid older metadata returns stale without replacing current, same-revision conflicts fail. ACK valid selection/duplicate/stale metadata only; malformed metadata is not ACKed and requires repair. Result schemas return null and remain owned by the result consumer, never silently dropped as metadata. One declaration and at most8 pending parses are retained; close is terminal.

Uncertain publication retains one exact request/raw/message ID. Only an explicit retry can resend the client's cached ciphertext; a different request cannot replace an uncertain pending one. Native descriptions revalidate current account/pass/profile/activity/folder/task/selected version and pair before preparation, before send and afterward. Scope change clears/closes rather than releasing a stale receipt. Revoke/logout/close discard publication and cipher state. Describing metadata uses the existing selected open document and does not invoke the journaled content-file reader or approve a request. An expired uncertain ciphertext cannot be refreshed under its original ID; repair requires explicit close/re-pair, without nonce/key reset or automatic new delivery.
