# Explicit native DEV companion host owner

CompanionDevHostOwner is an unregistered native lifecycle for an already prepared
workspace and existing AccountSession. It replaces fixture-global pair/relay/turn
references without another auth/workspace store, crypto implementation, endpoint,
poll, timer coordinator or production activation. Private clients are injected
structurally and must be fresh/exclusively owned by this owner; only budgets and
existing stores are shared. Product source imports no private sibling or package pin.

Construction/view perform no I/O. Explicit methods start an invitation, inspect
its current claim, confirm only the supplied previously inspected code, connect
the paired cipher, describe selected saved HTML and receive one host turn. The
existing preparation, authenticated transport, shared caller budget, task view,
epoch/journal, native bridge and HostSession own their established behavior.
Every pairing/status/relay HTTP and the authenticated transport initial /me
uses the same caller-owned budget; no second operation admission is nested.
Existing AccountSession refresh and native bridge /me/profile/activity authority
checks retain their existing implementations; this owner does not newly budget
those calls.
The owner never disposes the shared budget or existing stores.

Comparison approves pairing only. Exact-file consent, current profile/folder/
task/version checks and durable dispatch still govern each read. The safe view
contains state, optional pairing ID/comparison/expiry and terminal reason, always
executionAuthorized:false. The native-only challenge is returned separately for
explicit QR/copy; its invitation secret/public proof fields are not an account
bearer/private key and never appear in view/selected-file descriptors. The
mobile-facing descriptor comes directly from the bridge, with no path/content.

Owner lifetime binds account/session, configured Service/site, prepared workspace/
host/project/activity and active binding. DEV/loopback/match checks run before
credential access. Before/after awaited operations and admitted HTTP recheck the
binding. Post-fetch scope rejection cancels an unconsumed response body. Operations
are exclusive; concurrent receive callbacks share one turn. Abort/local close
suppress late publication, close relay/session and drop owned client, signing,
challenge, bridge and preparation references. This does not claim cryptographic
zeroization; a platform crypto call may settle before its last reference drops.

Local close is terminal and is not a signed remote revoke. Explicit revoke must
run while open and reports revoked only after client verification; uncertainty
closes locally as unconfirmed. Closed owners require a fresh explicit lifecycle,
not key/counter restoration from metadata.

## Caller lifecycle contract

This class installs no listener or watcher. Future native registration must call
close on the existing account/config/task/workspace/disposal events, including
while idle. Per-operation guards supplement that required caller contract. No
main extension or UI registration is included. The separately authored DEV palette
can consume this structural API without private package ownership.

## Author validation boundaries

Focused source controls use existing native preparation/bridge/account/task/
journal helpers with fixture-owned VS Code UI and clients. They cover explicit
comparison, independent native Cancel/Allow, scope/config/signout closure, pending
client work, abort, signed revoke, live response-body cleanup and production
refusal before credential access. Full extension TypeScript and compile-only
actual-package challenge/command-interface compatibility are checked.

A private actual Worker/D1 control injects real package clients and legitimate
synthetic sessions through unchanged raw native bearer HTTP. It exercises signed
pairing, code comparison, cipher connection, Cancel/Allow, exact selected artifact,
signed revoke and unchanged source. Challenge fields/public-key format are checked
against the actual package. The owner creates none of those accounts or grants.

Executed exact-head results accompany the commit in the private artifact report.
This author evidence is not installed-app/real-member acceptance. Registration,
private pin, Android/iOS/physical device, production, distribution, human and full
DMC acceptance remain NOT RUN/open. Existing canonical ST-REQ-COMPANION,
ST-DES-COMPANION and ST-TEST-COMPANION stay unchanged; root owns mapping and PRs.
