## CGP-SHELL-R-026 / CGP-SHELL-D-025: confirm before an external link opens (2026-11-14, Jay's scope, agent choices below)

Requirement: REQ-SHELL-26, DES-SHELL-25 (`domains/settings-account-shell.md`); `docs/studio-requirements.md` REQ-N11 "CGP-SHELL-R-026" clause. Supersedes CGP-ART-D-008's block for this scope (Jay, 2026-11-14, #4090).

- **Route (Jay).** Non-web input is refused as before (javascript:, file:, data:, blob:, about:, vscode:, mailto:, ftp:; no host).
  - Loopback opens in the integrated browser with no dialog.
  - Minor (safe-session) seats: an allowlisted link opens with no dialog. Any other link shows the confirm dialog, and nothing is blocked.
  - Adults: the system browser with no dialog. `hypeproofChat.confirmExternalLinks` (application scope, default false) turns the confirm on.
- **Agent choices confirmed by the coordinator (2026-11-14):**
  1. A minor's 열기 opens in the integrated browser (keeps CGP-ART-R-008).
  2. The browser panel is guarded through CDP (no core patch, no build).
  3. `hypeproofChat.safeLinkAllowlistEnabled: false` stops trusting the allowlist, so every external link confirms. It never removes the dialog.
- **Dialog (agent choice, forced by the platform).** VS Code's native modal always makes its first non-cancel button the default (`mainThreadMessageService._showModalMessage` moves the close affordance last; `abstractDialogHandler` sets `defaultId = 0`), so Enter would open the link. The dialog is therefore Studio's own `LinkConfirmDialog` in the chat webview, on the BrowserApprovalDialog pattern (`LinkConfirmRequest`: one prompt per seat scope, 120 s timeout, cancel on a scope change).
  - The host focuses the chat first. If the chat cannot draw the dialog, nothing opens and an info message says to open the chat (fail closed).
  - Buttons: 취소 (first focus; Enter on it cancels; Esc cancels), 열기, 링크 복사.
- **Host line (agent choice).** The WHATWG hostname, so an IDN shows its punycode, drawn bold and middle-ellipsized past 48 characters.
  - When it differs, the decoded form follows ("이렇게도 보여요: …").
  - An IDN label, or a label mixing scripts (Latin with Cyrillic, Greek, Hangul and others), adds the warning "다른 사이트를 흉내 낸 주소일 수 있어요. 주소를 한 글자씩 확인해 주세요."
  - Userinfo (`user:pw@`) is stripped from the shown and opened URL.
  - The full address follows on its own line, wrapping, never shortened.
- **The three entry points.**
  - *Chat* (links, citations, inbox links, Chalk runtime `openExternal`): `openLearnerLink`.
  - *Preview*: a click relay injected into the generated page posts `hp:open-link` for a trusted click (`isTrusted`) on an external `<a href>`. The shell forwards a bounded http(s) string. The isTrusted and anchor checks are defence in depth only, because a page script can post the same shape. **The host is the boundary:** every preview-originated open shows the confirm, for minors and adults alike, whatever `confirmExternalLinks` says, and at most one per 2 s (`LinkOpenLimiter`). A second one within 2 s is dropped with no dialog.
  - *Browser panel*: `LinkNavigationGuard` per browser tab over its CDP session. Every hold is at the network layer, before the request leaves (verify-3928's probes).
    - `Fetch.enable` holds every main-frame http(s) Document request at the request stage.
    - A request to another origin than the page, or than the hop before it, goes through the route and dialog (allowed: `continueRequest`; refused: `failRequest`) when it is (a) page-requested (`Page.frameRequestedNavigation`: a link, a script, a meta refresh, a form POST) or (b) a server redirect hop (`redirectedRequestId`), whoever started the chain.
    - ~~Navigations Studio, the learner's address bar or the coach's approved browser actions start are not held.~~ Superseded by the existing-window fix (2026-11-15, coordinator): every cross-origin main-frame Document is decided except a navigation Studio itself started. Same-origin moves and hops continue.
    - **Existing-window fix (2026-11-15).**
      - *The hole.* A form submitted by name into a window that already exists (a popup the page opened, or the opener) fires no `Page.frameRequestedNavigation` in the window it moves. The guard therefore let it go, GET, POST or `rel=noreferrer` alike, to any site (found by builder-shell-r027 while pinning verify-r027's time-of-check case). verify-r027 reproduced it with both layers on, the minor-seat configuration (verify-ew-baseline). A declarative shadow root, which layer 1 cannot see, holds a same-site link that opens `w2` (no decision, same origin) and a POST form into `w2` aimed at another site; the POST reached that site. A red-first test pins this path.
      - *Why the earlier rule could not stay.* The probe showed that over CDP such a load is indistinguishable from a browser-started one: the same `initiator: {type: "other"}`, no user gesture, the same `frameStartedNavigating`. VS Code core's address bar, back, forward and reload (`browserView.ts` `loadURL`, `navigationHistory`) never pass through the extension.
      - *Popups.* A popup session decides every cross-origin main-frame Document. Nothing in a popup is Studio-started.
      - *The page.* It decides every cross-origin main-frame Document except one Studio started. Anything else is decided (fail closed). The exemption (revised after verify-r027 on #4192, which showed a global, address-keyed record could be claimed by a page's own request, a `#hash` variant, a failed navigation's leftover, or another tab) is:
        - *Studio's `Page.navigate`* (browserControl, experimentBrowser, siteCheckRunner; `studioNavigate`): the record is keyed by the tab's target id. It is made just before sending, because Chromium may answer `Page.navigate` only after the paused request goes on, so a loaderId cannot be waited for. It is claimed once, only by that navigation's shape: the same tab, the same address without its fragment, a GET, and no Referer or Origin header. A page's own request carries a method or a header that rules it out. The one shape left, a no-referrer GET to the very address Studio is loading in that tab at that moment, takes the tab exactly where Studio was taking it. A failed (`errorText`) or thrown navigation removes the record; a 5 s TTL is only a backstop. Residual (verify-r027 round 2): a page that sets `<meta name=referrer content=no-referrer>` can send a GET form from another window into this tab, aimed at exactly the address Studio is loading there at that moment, and claim the record. The destination is the one Studio was loading. Query, host and cross-tab variants are decided, and so is a 302 off the origin. `Sec-Fetch-Site` would tell the two apart, but a paused request at the Request stage does not carry it: the probe found the browser-started load and that form header-identical. So it is documented, not coded.
        - *`openStudioTab`*: only the new tab's own first main-frame Document, once, and only while that tab has committed nothing (`studioFirstDocument`). Another tab's request to the same address is decided.
        - *Coach history moves* (`navigateToHistoryEntry`) return no loaderId and have no shape to match, so they are not exempt: a cross-origin back or forward by the coach is decided like the learner's.
      - *Cost (coordinator-accepted).* On adult seats with `hypeproofChat.confirmExternalLinks` on, an address typed in the bar, or back/forward across origins, asks. On minor seats it asks only off the lesson list. Loopback and allowlisted addresses never ask, and adults by default never ask (the route goes on).
      - *Later improvement (for Jay's next core batch).* A core patch that tags address-bar and history loads would remove that cost.
      - *Why it matters now.* The hardened safe session, which denies popups and filters off-list main-frame loads in core, is default-off: it is served only to the `studio-minor-device-check` cohort. So for real minor seats today this hole was live.
  - *Popups*, two layers:
    1. On minor seats the page's `window.open`, every link or form aimed at another window, and the script paths to them (`HTMLAnchorElement.prototype.click`, a dispatched click or auxclick on an anchor, `form.submit`/`requestSubmit`) are replaced before the page's scripts run (`Page.addScriptToEvaluateOnNewDocument` plus a `Runtime` binding). No popup is created; the address is decided like a link and, if allowed, opens as a Studio tab. A form aimed at another window is stopped. Since verify-r026 F4 (2026-11-15, agent choice) the stop is reported to the host with the form's action address, read through the prototype getter because a field named `action` shadows `form.action`. Fixed after verify-r027 on #4182: the form's `target` and the submitter's `formtarget`/`formaction` are read through the `HTMLFormElement`, `HTMLButtonElement` and `HTMLInputElement` getters too. Before the fix, a form aimed at this window that held a field named `target` was stopped and reported, which blocked legitimate submits. An empty `formaction` resolves to the document's address, as the HTML spec says. The guard caps reports at one per 3 s per action origin, so a stop to one site does not hide a stop to another. The host caps only the lines it actually shows, at one per 3 s per tab, so a silent on-list stop does not hide an off-list one a second later. A same-origin form or link aimed at a named iframe of the page is an in-page pattern, not another window, so it goes through (verify-3928). A cross-site one, or one aimed at a name no frame of the page has, is still stopped. The effective target is the element's own (a submitter's `formtarget` first) or else the page's `<base target>`. Before this, `<base target="_blank">` went round layer 1 and only layer 2's paused popup held it. The browsing-context keywords match ASCII case-insensitively, as the HTML spec says, so `_Self` is this window (verify-r027 on #4187). A submit event does not leave its shadow root, and a click inside one is retargeted to the host, so layer 1 used to miss a `_blank` form in a shadow root. It now puts its listeners in every shadow root, open or closed, as it is made (`Element.prototype.attachShadow` is wrapped and locked before the page runs). Layer 2 already held those popups on its own: refused, nothing reached the other site, both before the fix and with layer 1 off. So this was a gap in layer 1, not a minor-seat bypass. A declarative shadow root (`<template shadowrootmode>`) is made by the parser, not `attachShadow`, so layer 1 does not see it; layer 2 holds its popups, and a test pins that. Round 3 of verify-r027 (2026-11-15):
  - A named target is resolved by the child browsing context's name (`frames[i].name`), as the browser does, not by the iframe's attribute. A renamed frame's old attribute name is therefore another window. The name is read through the `name` getter captured before the page runs (verify-r027, folded into #4192): a same-origin child that redefines its own `name` cannot lie its way in-page. A cross-origin frame's name cannot be read, so it is never in-page. Tests pin both.
  - An empty `target=""` is no target, so `<base target>` applies.
  - A page listener that runs after layer 1's check and then removes the named frame or adds a base target is not seen by layer 1. Layer 2 holds the new window that opens, and a test pins that nothing reaches the other site.
  - **Found while testing, reported separately:** a form, GET or POST, submitted into an *existing* window by name (a popup the page already has, or the opener) is not held by layer 2. That session's rules decide only page-requested moves and redirects, and a cross-window form navigation fires no `Page.frameRequestedNavigation` there. On minor seats this needs a popup to exist first, which layer 1 normally prevents. Fixed by #4192 (popups decide every cross-origin document; the page exempts only navigations Studio itself started). Off the lesson list the learner gets the same `blocked` line as any refused address ("이 창에서는 수업 허용 목록 밖의 사이트를 열 수 없어요. 선생님께 알려 주세요."). On the list the stop stays silent, because that line would not be true there; this is a known gap. A form is still never replayed through the dialog: a POST cannot be resent safely.
    2. `Target.setAutoAttach` with `waitForDebuggerOnStart` on the tab's root session (and its page session) makes a popup that gets round layer 1 (for example `window.open` from a script-made frame) start paused. Its `Page.enable` and Fetch hold go in before it runs (sent in order with the resume; awaiting each reply first deadlocks a `noopener` popup), and from then on it has the page's main-frame rules for its whole life, with no one-shot shortcut: its first document is decided against its opener, and every later page-requested move or redirect hop to another origin is decided. A refusal of the first document fails it and closes the popup; a later refusal fails the request and the popup stays where it was. On minor seats the popup also gets the layer-1 replacement (without the binding), so it cannot open a further popup unseen. Other targets are let go at once. Tested against a two-origin recorder with both layers and with layer 2 alone: `window.open`, `target=_blank`, a detached anchor click, `form.submit` to `_blank`, and a popup that opens on this site and then 302s or sets `location` away.
    3. The ledger close (below) is the last resort if neither layer is available on a build.
  - *Fail closed at runtime (coordinator, 2026-11-14).* If a minor tab's session rejects `Target.setAutoAttach`, `Fetch.enable` or `Page.enable` (a VS Code build whose tab session does not behave like Chromium's), that tab falls back to the old allowlist block. A cross-site navigation or popup the list does not admit is refused, never confirmed, with the line "이 창에서는 수업 허용 목록 밖의 사이트를 열 수 없어요. 선생님께 알려 주세요.".
    - Without the network hold, a committed move off the list closes the tab.
    - Without navigation events, or with no CDP session at all, a tab off the list is closed.
    - Minors can therefore never fall below the pre-R-026 behaviour. Adults are not put in the fallback.
- **Removed.** `ExternalLinkBlocked` (the blocked notice and its 선생님께 알리기 prefill) and the `externalLinkBlocked` message.
- **Guards (coordinator, 2026-11-14).**
  1. *Nonce.* Each prompt id is a random UUID. The host acts only on the answer to its own pending prompt; the id is single use and expires with the timeout. A forged or replayed answer opens nothing.
  2. *Not drawable by content.* The dialog is mounted by App from the host message, outside the message-markdown path. MarkdownText shows raw HTML as text, so model output or chat content can draw no `<dialog>`, button or dialog class, and cannot answer it. Answers reach the host only from the dialog's own buttons.
  3. *One at a time: refuse.* While a dialog is open, a second request for the seat is refused with the line "먼저 열린 링크 확인 창에 답해 주세요.". The open dialog is neither stacked over nor replaced.
  4. *Real activation.* 열기 opens only on a trusted click (detail ≥ 1) or an Enter/Space keydown that starts on 열기 itself after the dialog opened. Repeated keydowns (a key held from the composer) activate nothing, and a scripted click does nothing.
- **Minor seats fail closed on the ways round the guard.** Every tab Studio opens goes through `openStudioTab`, which records it in `StudioTabLedger`.
  - A browser tab that appears with an address Studio did not open was opened by a page (`window.open`, `target=_blank`). On a minor seat it is closed at once and its address goes through the dialog; 열기 reopens it as a Studio tab.
  - A Studio tab whose page reached another site before the guard attached is handled the same way after attach.
  - Adults: both are a known gap, recorded here. Their pages open as before.
- **Known residuals.** On adult seats, popups and a navigation before attach (adult popups run; layer 2 still asks when an adult turns the confirm on). Cross-site subframes on minor seats were a gap found by verify-3928 (2026-11-15). They are now held (#4128, below). Cross-site subresources stay unheld, an accepted residual (below). Layer 2 relies on the tab's root CDP session reaching popups, as Chromium's browser endpoint does in the tests; this is to be checked on a real device. Also not run: a real screen reader and the installed app.
- **Unresolved: R-026 × the safe session (2026-11-15).** With the hardened safe session on, the session's `webRequest.onBeforeRequest` cancels every mainFrame load off its allowlist. It is not yet known whether a minor's 열기 on an off-list link (a confirmed R-026 open) actually loads, or is cancelled by core; nothing found adds the confirmed address to the session allowlist. This is added to #3561's real-device check plan as an explicit step. No code change until it is observed.

### CGP-SHELL-R-026: sub-requests from AI-made local pages on minor seats (2026-11-15, Jay)

- Chosen option: "로컬 페이지만 차단". On AI-made loopback pages, cross-site fetch, beacon, WebSocket and EventSource are blocked; images and CDN loads are unchanged.
