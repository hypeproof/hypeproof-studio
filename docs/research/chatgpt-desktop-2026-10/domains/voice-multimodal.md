## 0. Facts that shape all verdicts

- Studio voice is **planned, not shipped**. VO-01–47 are requirements; REQ-R1 records that the shipped
  webview iframe allow-list has no `microphone` and the Electron webview permission set has no `media`.
  The extension snapshot has only a capability probe (`voiceCapability.ts`, command-triggered) and pure
  decision helpers (`voicePopupHelpers.ts`, `voiceSessionHelpers.ts`). No capture code in
  `extensions/hypeproof-chat/src` (searched: `getUserMedia|MediaRecorder|AudioContext`, comments only).
- ADR-0009 (undecided) lists on-device STT/TTS and STT→text→TTS as options; Service rejects audio
  modalities on metered seats today (REQ-R3).
- Class feature narrowing (REQ-M38) has six keys: `read write shell subagents browser web_search`.
  **There is no `voice`, `dictation` or `read_aloud` key**, so an instructor cannot turn these on/off per class.
- Chalk: no voice/dictation coverage found (searched `chalk/README.md`, `chalk/src`, `docs/requirements/chalk-*`,
  `classroom-*` for `voice|음성|mic|dictat|speech`).
- Dictation (speech → composer draft) has **no requirement**; the only mention is VO-36 / `voicePopupHelpers.ts:72`
  ("the voice button's accessible name must be distinguishable from dictation").
- Read-aloud/TTS of answers has **no requirement** (searched `TTS|speechSynthesis|read aloud|읽어 ?주` in
  requirements/design; only ADR-0009 mentions TTS as a pipeline component).
- Korean IME: `REQ-STUDIO-CHAT-DETAIL` (CP-R1) keeps Enter/Shift+Enter/Korean IME semantics; no rule yet for
  dictation text arriving while an IME composition is open.

Product Intent principles (`docs/PRODUCT-INTENT.md`): #1 Useful work first, #2 Human judgment stays visible,
#3 Learning is embedded, #4 Minimum necessary intervention, #5 Evidence over claims, #6 Adapt, do not script,
#7 Capability models are hypotheses. Access intents (INT-ACCESS) are cited as "Access".

## 4. Open questions / unknowns

1. **Capture path is the gate for everything mic-based** (rows 01–03, 17–23, 38–39). REQ-R1/ADR-0009 are undecided; dictation and voice depend on the same core patch. Read aloud (24) does not need mic and could ship first: is that an acceptable sequencing for Jay?
2. **Dictation is not in VO-01–47.** Should it be a new section in `voice-conversation.md` (VO-48+) or its own requirement file? Elementary learners type Korean slowly, so this may be the most useful item in the domain. Product owner has to decide.
3. **Retention policy (VO-25)** decides REQ-CGPV-04/19 copy. Until it is decided, the disclosure cannot be written truthfully.
4. **Class feature keys** (REQ-CGPV-33): REQ-M38 says the key set is derived from compiled profiles. Do new keys need a Service profile schema change? Probably yes (Service repo, out of this snapshot).
5. **TTS for Korean**: ADR-0009 notes OpenAI TTS is "optimized for English" and Deepgram has no Korean TTS. Read-aloud quality for kids is unverified.
6. Feature flags: every row is `observed` as strings in the bundle; gating (Statsig gate in `realtimeVoiceDebug.statsigGate`, plan eligibility) means some surfaces (Meetings, Computer History, Codex Micro, pets) may not be live for typical users. Not verified at runtime.
7. `system-audio-spectrum` (row 40) usage is inferred (orb/pet visualization); the consumer chunk was not traced.
8. Students-specific ChatGPT voice use cases (`chatgpt.students.back_to_school_2026.onboarding.voice.*`: "Practice for an interview, rehearse a presentation") could become Chalk lesson templates. Not inventoried as a separate feature. Needs a Chalk-domain decision.
9. Memory NUX (row 50) was in this domain's namespace list but belongs with memory/personalization; the owner of that domain should give the verdict.
