Product Intent principle numbers used in "Traces to":
#1 Useful work first, #2 Human judgment stays visible, #3 Learning is embedded,
#4 Minimum necessary intervention, #5 Evidence over claims, #6 Adapt, do not script,
#7 Capability models are hypotheses, not UI labels. "AB" means the access/pricing principles
in the same doc (limits never hide own results/files/export; tokens are not capability scores).

Labels: **observed** = string or code present in the bundle. **inferred** = my reading of the
behavior. A bundled string does not prove the surface is enabled for every account; several
of these are clearly gated (`.space` variants, `internalOnly`, `[Employee only]`, "Upgrade").

## 4. Open questions / unknowns

1. **cr-memory (#1450) is open.** REQ-KNOW-07/40–49 assume Studio adopts memory at all. The
   preferred shape (CGP-KNOW-48) is file-based memory inside the activity, building on the team
   brain, not a hidden server profile. Jay/Service owner must decide whether any server-side
   memory exists and who can read it (instructor? Service operators?).
2. **Minor consent path.** Who switches memory on for a minor cohort: instructor in Chalk,
   guardian, or neither? `session-log-consent.ko.md` covers session logs, not memory.
3. **Gating unknowns in ChatGPT.** Library (`libraryNext`, `.space` variants), profile
   showcase ("Upgrade to edit your showcase"), stickers (`internalOnly`), flashcards and
   Chronicle are present in the bundle, but whether they are enabled for all accounts is
   unknown. Inventory rows are labelled observed for strings only.
4. **Trash retention.** ChatGPT uses 30 days. REQ-KNOW-24 proposes "life of the activity";
   disk cost on class PCs and what happens at activity removal (US-10 says no automatic
   project deletion) need a decision.
5. **Adult archive vs learner versions.** `adultArchive.ts` keeps history only on adult
   orchestrator seats. REQ-KNOW-30 extends this to minor seats; check if the original
   restriction was deliberate (e.g. storage on school PCs).
6. **Provenance source of truth.** REQ-KNOW-21/29 depend on spool/version events
   (`sessionSpool.ts`, `artifactVersion.ts`). Files edited outside Studio (Finder, another
   editor) have no event; the "확인 안 됨" label covers this, but coverage on Windows is unverified.
7. **Downloads in the native browser.** No current spec mentions downloads
   (`native-browser-spec.md`, §N). Whether Electron's default download prompt already appears
   in Studio is unknown; it needs an observation on the installed app.
8. **Team projects (CGP-KNOW-08) and the founder course.** Team brain is per workspace; shared
   team memory across several learners' PCs has no contract yet.
9. **Chalk starters (REQ-KNOW-70)** need a schema field in the authoring batch
   (`hps-authoring-batch/1`) and a frozen-version compatibility check; not yet designed.
10. Search used for "no coverage" claims was bounded to the `studio@origin/main:` snapshot docs and
    `extensions/hypeproof-chat/src` file headers; Service (`hypeproof-service`) source was not
    available here, so Service-side memory or storage features may exist unseen.
