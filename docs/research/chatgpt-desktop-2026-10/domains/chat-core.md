# ChatGPT desktop → Studio/Chalk parity: CHAT core (`chat-core`)

Source app: ChatGPT macOS desktop v26.1013.40934 (`com.openai.codex`). Evidence base:
`findings/messages-en.json` (message id → English default + bundle chunk) and the
Studio snapshot `studio@origin/main:` (origin/main). All ChatGPT strings are quoted verbatim.

Scope covered: `composer.*` (1,155 msgs), `composerTips`, `chatgpt.*` chat-turn
sub-namespaces, `chatgptConversations.*` chat sub-namespaces, `localConversation.*`
(turn/timeline items only; the 901 `mcpToolActivity` strings were sampled, not
enumerated), `localConversationPage`, `thread`, `threadHeader`, `threadPage`,
`assistantMessage`, `assistantMessageContent`, `markdown`, `latex`, `code`, `diff`,
`turnRatingControls`, `feedback`, `sectionedConversation`, `quickChat`,
`floatingComposer`, `hotkeyWindow`, `appUndo`, `emoji`, `symbolPicker`,
`safetyBuffering`, `requestInputPanel`, `elicitation`, `keyboardShortcutsDialog`,
`navigation`, `sidebar`, `sidebarElectron`, `home`, search keys, `multiplayer`,
`lockedChats`, `shareDialog`, `replay`, `toolSummaryForCmd`, and model-picker /
reasoning-effort keys found anywhere. Extra chat-surface namespaces picked up:
`messageActions`, `copyButton`, `codeSnippet`, `codeBlock`, `mermaidDiagram`,
`ConversationTurn`, `MessageError`, `reasoningItem`, `thinkingShimmer`,
`threadUsagePopover`, `selectedTextOverlay`, `sendUserMessageQuestion`,
`optionPickerRequest`, `responseTextAnnotationMarkers`, `tokenBudget`.

Out of scope here (left to other domains even when they appear in chat): image
generation, voice/realtime, memory settings, projects/library, plugins/MCP catalogue,
Codex git/PR/review, billing/checkout, learning blocks, artifacts/canvas.

Evidence discipline: every row in the ChatGPT column is `observed` (a string ships in the
renderer) unless marked `inferred`. A string does not prove that the feature is on for
every account (flags are not resolved here). Studio's React webview source is **not**
in the snapshot (`extensions/hypeproof-chat/src` holds the host only), so Studio
"today" is cited from requirement docs and host files. A doc row proves only that a
requirement exists, not that it is shipped.

Studio references used:
- `docs/studio-requirements.md` (REQ-C*, REQ-M*, REQ-STUDIO-CHAT-DETAIL / -REFERENCE / -TASK-WORKSPACE, …)
- `docs/requirements/studio-native-trial-ux.md` (TUX-CHAT-01…16)
- `docs/requirements/learning-agent-experience.md` (AE-01…44)
- `docs/design/task-workspace.md` (740px column, composer 192px cap, motion 180/160/140ms)
- `docs/requirements/voice-conversation.md` (VO-*)
- `extensions/hypeproof-chat/src/protocol.ts` (webview↔host message types)

Product Intent principles (`docs/PRODUCT-INTENT.md`): **#1** Useful work first, **#2** Human
judgment stays visible, **#3** Learning is embedded, **#4** Minimum necessary
intervention, **#5** Evidence over claims, **#6** Adapt, do not script, **#7** Capability
models are hypotheses, not UI labels.

## 4. Open questions / unknowns

1. **Flags not resolved.** Many surfaces (Goal mode, Steer, Daybreak, side chat,
   sectioned conversation) may be gated. Their presence in strings proves shipping code, not
   availability. If parity is measured against the live app, someone needs to record which of these are on
   for a normal Plus/Edu account.
2. **Studio webview source absent from the snapshot.** "ALREADY" rows cite requirement
   docs. Whether e.g. TUX-CHAT-15 Markdown or CP-R1 copy actually ships in the current
   React build was not verified here.
3. **Edit-and-resend vs evidence (R65).** Should the original prompt/answer count in the
   observation record as a separate attempt (it is a real iteration signal), or be hidden
   from the instructor view? Needs a measurement-core decision (MC-*).
4. **Learner verdict storage (R63).** Local spool event only, or also visible to the instructor
   in Chalk as an operating signal? AE-20 forbids raw-content surveillance, so a decision is needed.
5. **Steer (R04) runtime support.** Unknown whether the Agent SDK / proxy paths accept
   mid-turn user input. If neither does, the row degrades to DEFER.
6. **Read-aloud / dictation metering.** Is TTS/STT inside the existing request unit
   (PRODUCT-INTENT: one request = one unit regardless of model) or a separate audio
   entitlement (REQ-R3)? It affects whether elementary cohorts get it by default.
7. **Plan mode vs AE-36 help modes.** Is "먼저 계획 보기" a fifth help mode chosen by the
   instructor in Chalk, or a learner toggle? The current draft says the cohort profile decides
   availability and the learner toggles it.
8. **Math rendering (R40).** Is there any curriculum need beyond adult courses? If not,
   move it to DEFER. Interim (2026-10-25, DEC-32 in decisions.md): built for every seat as display only;
   Jay can still move it to DEFER.
9. The 901 `localConversation.mcpToolActivity.*` strings were sampled only. They describe
   per-connector verbs (Figma, Drive, …) that the plugins domain should inventory.
10. **Conversation copy scope (R62, decided 2026-10-25, agent choice).** 대화 내용 복사 ships in
    the personal task menu only; classroom, lesson and instructor seats have no task menu, so
    their copy is a follow-up. It copies visible learner/coach text only and applies the AE-39
    exclusions. See decisions.md "CGP-CHAT-R-024". CGP-CHAT-D62 (CGP-CHAT-D-024, 2026-10-26): the result
    uses the answer-copy toast (same outlet, icon, chrome and 160ms entry).
11. **Shortcut sheet keys (R86, decided 2026-10-25, agent choice).** The sheet lists only keys
    the chat webview binds today: Enter, Shift+Enter, Esc (close), Alt+Shift+J (personal task
    layout) and `?`. Esc-to-stop, Cmd/Ctrl+F and a focus-composer key are not bound, so they are
    not listed and not invented here. See decisions.md "CGP-CHAT-R-030".

**CGP-CHAT-R19 tip source (2026-10-25, owner decision).** The served step has no tip key, so the
lesson tip is the step's Chalk-authored `hint`, and its action prefills that hint. See
`CGP-CHAT-R-021` in `decisions.md`.
