## 4. Open questions / unknowns

1. Gating: many surfaces here are flag- or plan-gated (`automations.configuration.triggersUnavailable`, `workspaceAgents.legacyRoute.description`, `plugins.dependencies.planStatus`). I did not determine which are on for a default Plus/Free account; strings prove shipping only.
2. "Approve for me" mechanics: strings show an AI reviewer with rationales and a credit cost, and main code merges `approvalsReviewer` with `allowedApprovalsReviewers`. Whether the reviewer is a separate model call per action was not traced.
3. Should approval presets (REQ-CGP-AGENT-01a) be per lesson or per lesson step? AE-10 allows per-step teaching strategy; presets per step would multiply rehearsal cases (AE-11).
4. Plan mode (REQ-CGP-AGENT-14) needs a decision on whether the plan approval counts as the learner's judgment evidence or as AI output (AE-35 forbids recording AI recommendation as learner judgment). Proposal: only learner edits/approval are evidence.
5. Notifications: does VSCodium's notification API reach macOS Notification Center reliably for a built-in extension, and does Windows x64 behave the same? Unverified.
6. Chalk scheduling (REQ-CGP-AGENT-19) depends on a Service scheduler; the current Service is HTTP-only Worker (chalk/README.md). Cron triggers availability and cost not checked.
7. Subagent panel (REQ-CGP-AGENT-12): which SDK events carry child-agent status and final text in Agent SDK 0.3.207? Not inspected.
8. `codex.space`/`codex.pages` (978 strings) were only skimmed for automation/agent-instruction hooks; the documents domain should own their inventory.
9. Skill format: Studio could adopt the shipped `SKILL.md` + `agents/openai.yaml interface` shape for Korean display names and icons; whether Claude Agent SDK skills accept the extra interface file without warnings is unverified.
