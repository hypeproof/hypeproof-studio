# 수업 코드 한 번으로 좌석 연결 · 2026-11-12 (E5 #3778)

> 작성일 2026-11-12 · 상태: 활성 · 상위: [원격 수업 운영](classroom-admin.md), Epic #751, DEC-029·030

## 문제

재직자 수업은 성인 20–30명이 한 교실에서 하루 7시간 듣는다. 지금은 강사가 좌석마다 12자리 일회용 코드를 만들어
나눠 주고 수강생이 10분 안에 직접 입력해야 좌석이 연결된다(`POST …/pairings` → `POST /v1/classroom/ops/connect`).
30명이면 강사는 코드 30개를 만들고 누가 어느 코드를 받았는지 맞춰야 한다. 10분이 지나거나 다른 사람 코드를
입력하면 다시 만들어야 한다. 질문 카드(#3776)는 "지금 연결된 수강생"에게 가므로 연결이 늦으면 카드도 늦다.

## 결정

수업 실행(run)마다 **수업 코드 하나**를 강사가 화면에 띄운다. 수강생은 그 코드를 입력하고 앱은 수강생이 이미 가진
**수업 학습 토큰**(명단의 handle이 들어 있는 토큰)을 함께 보낸다. Service는 토큰의 handle로 그 수업의 좌석을 찾아
연결한다. 코드는 좌석을 가리키지 않는다. 기존 좌석별 12자리 코드는 그대로 동작한다.

| 항목 | 계약 |
|---|---|
| 만들기 | `POST /admin/cohorts/:cohort/classroom/runs/:run/join-codes` `{ttl_minutes?}`. 권한 `manage`, 배정 강사만(#3775), 수업 플래그 `ops_observe`가 켜져 있어야 한다. 기본 60분, 최대 480분, 수업 종료 시각을 넘지 않는다 |
| 코드 형식 | 혼동 문자(0·O·1·I·L)를 뺀 영문 대문자·숫자 8자, 화면에는 `XXXX-XXXX`. 저장은 SHA-256 해시만 한다. 응답에서 한 번만 평문으로 준다 |
| 한 수업에 하나 | 새 코드를 만들면 그 수업의 이전 코드는 즉시 폐기된다(`superseded`) |
| 폐기 | `DELETE …/join-codes/:id`. 폐기 뒤 그 코드로는 아무도 새로 연결하지 못한다. 이미 연결된 좌석은 그대로다 |
| 현황 | `GET …/join-codes`: 살아 있는 코드의 id·만료·만든 강사·연결 수. 평문 코드는 다시 주지 않는다 |
| 수강생 연결 | `POST /v1/classroom/ops/join` `{code, app_instance_id, boot_id, protocol, capabilities, app_version}` + `Authorization: Bearer <학습 토큰>`. 응답은 `/connect`와 같다 |
| 좌석 찾기 | 토큰의 cohort·profile이 코드의 수업과 같고 토큰의 handle(`u`)이 그 수업의 현재 좌석(`class_run_seats`, `replaced_at IS NULL`)에 있어야 한다. 없으면 403 `seat_not_found`(“이번 수업 명단에 없습니다. 강사에게 알려 주세요.”) |
| 보호 유지 | `/connect`와 같은 연결 grant를 만든다. 새 기기 등록 id, 좌석의 `connection_epoch` +1, 같은 좌석의 이전 연결 `device_replaced` 폐기(마지막 창이 이긴다), 배포 재전달(`deviceRebindStatements`)이 그대로 적용된다 |
| 토큰 검사 | 학생 토큰만 받는다(issuer 토큰 403). 서명·만료·KV 폐기·코호트 명단·프로필-코호트 일치를 채팅과 같은 규칙으로 본다 |
| 실패 제한 | 실패한 시도만 센다. IP당 1분 30회(기존 `/connect`와 같은 KV 카운터), 코드당 1분 60회. 코드가 틀렸을 때·만료됐을 때·폐기됐을 때는 같은 답(403 `code_invalid`)을 준다 |
| 감사 | `join_code_created`·`join_code_revoked`·`device_connected`(detail에 `via: 'join_code'`, code id) |
| 저장 | 새 테이블 `class_run_join_codes`(추가 전용 migration). 코드 해시·만료·상태·만든 강사·연결 수만 담는다 |

### 수강생 화면

1. ‘수업 연결’을 누르면 먼저 수업 참여 데이터 안내가 뜬다(#3781). 동의하지 않으면 여기서 끝난다.
2. 입력 칸은 “강사가 화면에 띄운 수업 코드(8자리) 또는 좌석 코드(12자리)”를 받는다. 8자리면 수업 코드로, 12자리면
   기존 좌석 코드로 처리한다.
3. 수업 코드로 연결하기 전에 “handle **s07**(으)로 이번 수업에 연결합니다.” 확인을 한 번 보여 준다. handle은 앱이
   가진 학습 토큰에서 읽는다. 학습 토큰이 없으면 “먼저 수업 참여 코드로 Studio에 들어온 뒤 다시 연결하세요.”라고
   말하고 아무것도 보내지 않는다.
4. 연결되면 기존과 같은 “수업에 연결했습니다 (좌석 A3).” 안내가 뜨고 동의를 기록한다.

### 강사 화면 (Chalk `/manage`)

- 운영 패널의 연결 영역에 ‘수업 코드 만들기’ 버튼. 만든 코드는 크게(32px 이상) 보여 주고 만료 시각과 “이 수업 명단에
  있는 수강생만 연결됩니다”를 함께 쓴다. 코드는 그 탭의 `sessionStorage`에만 둔다.
- ‘코드 폐기’ 버튼. 연결 수(이 코드로 연결된 횟수)를 보여 준다.
- 좌석별 12자리 코드 발급은 그대로 남긴다(명단에 없는 좌석 교체·다른 기기 복구용).

## 위협과 판단

| 위협 | 판단 |
|---|---|
| 코드가 교실 밖으로 퍼짐 | 코드만으로는 연결되지 않는다. 그 수업 명단에 있는 handle의 학습 토큰이 함께 있어야 한다. 학습 토큰은 강사가 이미 수강생별로 발급한 것이다 |
| 학습 토큰 유출 | 지금도 그 토큰으로 채팅을 쓸 수 있다. 수업 코드는 "교실에 있다"는 증명을 하나 더 얹는다. 좌석은 마지막 창이 이기므로 탈취 연결은 본인이 다시 연결하면 끊긴다 |
| 무차별 대입 | 8자·31종 문자 = 약 8.5×10¹¹. 실패 제한(IP·코드)과 짧은 수명, 수업당 하나로 충분하다 |
| 다른 수업 좌석 연결 | 코드는 한 run에만 묶이고 토큰의 cohort·profile이 그 run과 같아야 한다 |
| 미성년 | 연결 자체는 막지 않는다(기존 좌석 코드와 같다). 수업 참여 데이터 동의는 성인만 할 수 있다(#3781) |

## 검증

- Service: `worker/test/classroom-join-code.test.mjs` — 만들기·폐기·대체, 명단에 없는 handle, 다른 코호트 토큰,
  issuer 토큰, 만료·폐기 코드 동일 응답, 실패 제한, 연결 뒤 epoch 증가와 이전 기기 폐기, 배정되지 않은 강사 403.
- App: 8자리 입력이 학습 토큰과 함께 `/join`으로 가고 학습 토큰이 없으면 아무것도 보내지 않는다.
- Mac dev host(#3779): 강사가 코드를 띄우고 두 창이 같은 코드로 각자 좌석에 연결된다.
